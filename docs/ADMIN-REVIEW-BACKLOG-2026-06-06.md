### H2. DataProtectionLogPage - correctness (small) - RESOLVED 2026-09-04
- **Observation:** The backlog questioned whether server-side DSR overdue and due-soon comparisons were timezone-safe and proposed converting `timestamptz` values to Manila wall-clock timestamps.
- **Resolution:** Rechecked the current service and did not apply that conversion. `due_at < NOW()` and `due_at - NOW()` compare absolute instants in PostgreSQL, and `mapDsr` computes `daysUntilDue` from `Date` millisecond instants. The admin UI formats the resulting instant in `Asia/Manila` for display. Converting one side with `AT TIME ZONE` would change the type to a wall-clock timestamp and could introduce a false offset rather than fix one. The existing SQL and mapper tests cover the intended contract.
- **Evidence:** `packages/api/src/services/compliance.service.ts` (`mapDsr`, `listDsrs`, `getDsrAlerts`); `packages/api/__tests__/compliance-admin.test.ts`; `apps/admin/src/pages/DataProtectionLogPage.tsx`. No runtime change was needed.
